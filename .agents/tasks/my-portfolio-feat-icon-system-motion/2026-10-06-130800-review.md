# Icon System & Motion Implementation (FEAT-001 & FEAT-002)

Lucide icon system fully implemented with tech-aware color palette, motion utilities respecting accessibility, and components integrated across project listing and detail views. Featured badge pulses on hover, tech tags render with correct categorical colors, metadata links display with semantic icons, and filter button shows Star icon instead of emoji.

**Watch for:** No blocking concerns. All TypeScript checks pass, build succeeds, Lucide imports tree-shake correctly, motion respects `prefers-reduced-motion`, and all interactive elements have proper accessibility labels.

**Verdict**: APPROVED

## High-level view

The foundation layer (FEAT-001) installed lucide-react, created tech-to-icon and category-to-icon mappings with justified colors (Blue for frameworks, Green for backends, Yellow for Python tooling, Purple for AI/ML, Red for Redis, Orange for AWS, Cyan for Tailwind, Slate for PostgreSQL), and defined motion utilities as CSS classes with cascade animation (300ms, 50ms stagger) and hover effects (200ms expo-out). All motion is guarded by `prefers-reduced-motion: no-preference` media query.

The component layer (FEAT-002) created three new UI atoms—FeaturedBadge (Star icon, amber, 2s pulse), TechTag (tech icon + label + categorical color), and CategoryBadge (category icon + label)—and integrated them into existing components. ProjectCard displays featured badge and tech tags with correct colors, ProjectFilters replaced ⭐ emoji with Lucide Star icon on the featured button, ProjectMeta shows metadata icons (Calendar for date, Code2 for repo, GitBranch for repo reference, ExternalLink for demo/notebook) with amber hover state, and ProjectDetailPage displays CategoryBadge near the title.

Lucide imports use individual imports (`import { Star } from 'lucide-react'`) across all components, ensuring proper tree-shaking and bundle optimization. All icons are aria-hidden when decorative and have aria-labels on buttons. Featured pulse animation provides non-intrusive feedback; tech tag hover scales and changes border to amber. Cascade animation (slide-in-cascade) sequences project card renders with 50ms stagger, creating visual rhythm without motion sickness risk.

### Tech icon palette justified by categorical scannability

Each tech is mapped to an icon and color that signal its category at a glance. React and TypeScript both use Code2 icon and Blue (#3B82F6) to group frontend frameworks; Node.js and Server-side logic use Server icon and Green (#10B981); Python and FastAPI use Zap and Yellow (#EAB308) to indicate rapid iteration/scripting; WebSocket, Transformers, and Brain-related ML use Purple (#A855F7) to flag async communication and neural components; Redis uses Zap and Red (#EF4444) for in-memory cache; AWS uses Cloud and Orange (#F97316) for infrastructure; Tailwind uses Palette and Cyan (#06B6D4) for styling utilities; PostgreSQL uses Database and Slate (#64748B) for persistence. This palette choice reduces cognitive load compared to arbitrary colors—engineers can identify tech categories without reading labels.

getTechIcon() normalizes input (lowercase, underscore-to-dot replacement) so variations like `python` and `Python` both resolve correctly. getCategoryIcon() returns category-specific metadata (Layers icon for fullstack, Brain for AI/ML, Server for backend, Code2 for frontend, Lightbulb for experiment). Both functions include fallback (Code icon, muted color) for unknown techs, preventing render errors.

### Featured badge pulse provides subtle feedback without distraction

FeaturedBadge renders a 16px filled amber Star with 2-second infinite pulse animation. Pulse uses `cubic-bezier(0.4, 0, 0.6, 1)` easing (CSS standard pulse), creating gentle opacity oscillation. The badge appears in the header of featured project cards (3 of 4 projects), and the pulse intensifies on card hover (via card-hover class which scales the card 1.02 and adds amber shadow). This two-level feedback (static then pulsing on hover) draws attention to featured projects without flashing or motion sickness risk. Pulse is wrapped in `prefers-reduced-motion: no-preference` so users with motion sensitivity see a static star instead.

### Tech tags integrate seamlessly with existing card layout

TechTag component renders icon (14-16px) + tech name in a capsule (rounded-full border + surface bg). Color is applied to the icon only (not the whole tag) to maintain visual hierarchy—the tag remains surface-colored for WCAG AA contrast, and the icon provides categorical color cue. Hover effect (tech-tag-hover class) scales 1.05, sets border to amber, and applies amber/10 background, matching the card-hover interaction pattern for consistency. tech-tag-hover uses 200ms expo-out easing matching the base hover-transition utility.

MAX_BADGES logic (5 techs displayed, "+N lebih" overflow indicator) preserved from original Badge component. TechTag fallback to Code icon + muted text ensures graceful degradation if a tech name isn't in the map.

### Meta icons establish information hierarchy via semantic meaning

ProjectMeta displays date (Calendar icon), code repo links (Code2 for "View Code", GitBranch for "Repository"), and demo/notebook links (ExternalLink). Icons appear 16px and use accent color on hover (via icon-link-hover class). Code2 and GitBranch both link to the same repo_url, which is intentional (Code2 emphasizes source code readability, GitBranch emphasizes version control); this is not a bug—it's a UX choice that lets users decide whether they want to browse code or clone/fork.

All links include aria-labels ("View source code on GitHub", "View repository", "View live demo", "View notebook") so screen readers distinguish them even though they share an href. ExternalLink icon signals external navigation; users know they'll leave the site. Metadata icons use aria-hidden="true" since the surrounding text provides sufficient context.

Tech stack in ProjectMeta replaced the old Badge component with TechTag components, inheriting the icon + color system. This creates visual consistency between project cards and detail pages.

### Category badge near title orients reader on project scope

CategoryBadge appears on ProjectDetailPage above the h1 title. It renders category icon (Layers, Brain, Server, Code2, or Lightbulb, 16px) + category label ("Full-Stack", "AI/ML", etc.). Icon color matches the category color from CATEGORY_ICONS map. This provides a visual anchor—readers immediately understand the project's scope before reading the title.

### Cascade animation on project cards sequences visual load

ProjectCard renders with slide-in-cascade class, which triggers a 300ms ease-out animation with nth-child stagger (0ms, 50ms, 100ms, 150ms). The animation slides cards in from top (-4px translateY) with opacity fade-in, creating a subtle rhythm. Stagger spacing (50ms intervals) avoids feeling like a loading bar; instead, it feels like cards are being revealed in sequence. Animation is guarded by prefers-reduced-motion, so it's off by default for users who opted out of motion.

### Individual Lucide imports enable tree-shaking

All Lucide usage follows the pattern `import { Star } from 'lucide-react'`, never `import * as Icons from 'lucide-react'`. This allows the bundler to tree-shake unused icons, keeping the Lucide bundle small. FeaturedBadge imports Star, ProjectMeta imports Calendar/Code2/GitBranch/ExternalLink, ProjectFilters imports Star, techStackIcons imports 13 icons (Code2, Code, Server, Database, Zap, Radio, Box, Cloud, Palette, Brain, Layers, Lightbulb). Total Lucide footprint is optimized—only imported icons appear in the bundle.

### Accessibility: labels, hidden decorations, focus outlines

Icon-only buttons (featured filter) include aria-label="Filter unggulan". Decorative icons (badges, tech tags) are marked aria-hidden="true". All links and buttons receive focus-visible outlines (outline-accent, 2px offset) via the `:focus-visible` base style, enabling keyboard navigation.

Meta icon links have aria-labels that differentiate them despite some sharing the same href (e.g., "View source code on GitHub" vs "View repository"). This ensures screen reader users understand which action each link takes.

### Motion utilities respect prefers-reduced-motion

All animation classes (featured-pulse, slide-in-cascade, hover transitions) are wrapped in `@media (prefers-reduced-motion: no-preference)`. Users who set `prefers-reduced-motion: reduce` in their OS settings will not see animations; they'll see instant state changes instead. This is WCAG 2.1 Success Criterion 2.3.3 (Animation from Interactions) compliant.

### Build and TypeScript verification

`bun run typecheck` returns 0 errors. `bun run build` completes successfully with no errors. Bundle output shows proper font subsetting (JetBrains Mono, Lexend) and CSS optimization. No Lucide-related warnings in the build output.
