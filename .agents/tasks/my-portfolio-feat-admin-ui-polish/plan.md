Confirmed bugs in globals.css (checked compiled CSS): `@apply bg-[--color-bg] text-[--color-fg]` compiles to `background-color:--color-bg` (invalid in Tailwind v4), same for `::selection` and `:focus-visible { outline-[--color-accent] }`. So body has no real background and the global focus ring color is invalid. Fix with `@apply bg-bg text-fg;`, `bg-accent/20 text-fg`, `outline-2 outline-offset-2 outline-accent`. This also corrects the public site's body color to the intended token (intended design, minimal visual change).

## Key decisions

- Button className merge: `cn()` (src/lib/cn.ts) only joins strings; with Tailwind v4 the conflicting utility that appears later in the generated CSS wins (`.bg-surface` is emitted after `.bg-red-600`), so `className="bg-red-600"` on a secondary Button loses. Fix by adding real variants (`danger`), never overriding colors via className; className stays for layout (w-full, etc.). No tailwind-merge (no new deps). Also export `buttonClasses({variant,size,className})` so `<Link>` can look like a button instead of nesting `<Button>` inside `<Link>` (invalid nested interactive).
- Category labels: reuse existing `CATEGORY_LABELS` in `client/src/config/constants.ts` (already used by public ProjectCard/ProjectFilters) as the single source, but update its values to `fullstack: "Fullstack"`, `ai_ml: "AI/ML"`, `frontend: "Frontend"`, `backend: "Backend"`, `experiment: "Experiment"` per the task. Add `STATUS_LABELS: Record<ProjectStatus,string>` = Draft / Published / Archived (current copy). Used in dashboard rows, dashboard filters and ProjectForm selects (replaces the broken `"Ai ml"` label generator).
- Status badge: published → Badge `success`, draft → Badge `warning`, archived → new Badge `neutral` variant (`bg-border text-muted`). Featured → small `text-accent` "Featured" Badge.
- Admin shell: top header (not sidebar) — only one admin section exists (Proyek), a sidebar would be empty. Sticky `bg-surface/95 border-b border-border` header: brand link "Portfolio Admin" → /admin, NavLink "Proyek" (end), right side "Lihat Situs" link to `/` (new tab, `rel="noopener noreferrer"`, visible label), username from `useMe`, Logout button (moved out of DashboardPage). SkipLink reused.
- Mobile table: card list below `md` (`md:hidden`), real `<table>` at `md+` (`hidden md:block`) wrapped in `overflow-x-auto`. Cards are more usable than horizontal scroll on phones.
- Stats: no stats endpoint and backend must not change, so derive counts from `pagination.total_items` using 4 cheap queries with `limit=1` (all / published / draft / archived) in a `useAdminProjectStats` hook under the same query-key root so create/update/delete invalidation refreshes them.
- Pagination: the admin list currently uses `apiGet` which returns only `envelope.data`, so `pagination` is always undefined and pagination never renders (confirmed in code). Switch `getAdminProjects` to `apiFetchEnvelope` and return `ProjectListResponse<ProjectListItemDTO>` (same as public `getPublicProjects`). Reuse the public `components/projects/Pagination.tsx`.
- Error messages: `ApiClientError` calls `super()` with no message, so every `err.message` is `""` (ProjectEditorPage/ProjectForm/Login rely on it). Pass the server message: constructor gets `message` param, `super(message)`. Non-JSON responses (server down → proxy 500/HTML) make `response.json()` throw; wrap and throw `ApiClientError(response.status, "INTERNAL_ERROR", "Tidak dapat terhubung ke server")`.
- Login redirect bug (user messages 5/6/8/10: "login but doesn't move to dashboard"): `useLogin` only invalidates `["auth"]`; the `["auth","me"]` query is inactive on the login page, so after `navigate("/admin")` ProtectedRoute sees the cached error/null state (`isError || !data`) and bounces back to /admin/login. Fix: `onSuccess: (user) => queryClient.setQueryData(["auth","me"], user)` (login returns `{id, username}`, same as /me). Must be verified in the browser.
- `useAdminProject(id || "")` runs on /admin/projects/new and fetches `/api/v1/admin/`; add `enabled: id.length > 0`.
- Dashboard search: debounce with existing `useDebouncedValue` (300 ms) and `placeholderData: keepPreviousData` so the page doesn't swap to a full-screen spinner on every keystroke (which unmounts the search input and drops focus).
- Toasts: `LazyToaster` (sonner, dark) is already mounted in App.tsx; use `toast.success/error` from "sonner" for delete/save/logout feedback.
- Markdown editor: wrapper already has `data-color-mode="dark"`, but the lib's dark palette is GitHub (#0d1117), not our tokens. Add an unlayered override in globals.css on `.admin-md-editor` mapping `--color-canvas-default`, `--color-canvas-subtle`, `--color-border-default`, `--color-border-muted`, `--color-fg-default`, `--color-fg-muted`, `--color-accent-fg`, `--md-editor-background-color` to our tokens (var names verified in node_modules/@uiw/react-markdown-preview/markdown.css and react-md-editor/markdown-editor.css).
